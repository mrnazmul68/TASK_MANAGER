# Task Vault — Monorepo Instructions

Monorepo managed with **pnpm workspaces** + **Turbo**. `pnpm@11` is the package manager.

## Structure

| Path | Purpose | Entrypoint |
|------|---------|------------|
| `apps/frontend` | Next.js 16 app (React 19, Tailwind v4) | `src/app/page.tsx` |
| `apps/backend` | Express 5 + TypeScript API, MongoDB/Mongoose | `server.ts` |
| `packages/shared` | Shared TS utilities (`@task-vault/shared`) | `src/constants.ts`, `src/http/validation.ts` |

Path aliases in `apps/backend/tsconfig.json`: `@app`, `@modules/*`, `@config/*`, `@routes/*`, `@middlewares/*`, `@shared/*`, `@dts/*`, `@utils/*`.
Frontend alias: `@/*` → `./src/*`.

## Commands (run from repo root unless noted)

| Goal | Command |
|------|---------|
| Install all deps | `pnpm install` |
| Run everything (dev) | `pnpm dev` |
| Build everything | `pnpm build` |
| Lint everything | `pnpm lint` |
| Typecheck everything | `pnpm check-types` |
| Format | `pnpm format` (prettier over `**/*.{ts,tsx,md}`) |

### Backend (`apps/backend`)

Scripts: `dev` (`tsx --env-file=.env --watch server.ts`), `build` (`tsc`). No test/lint scripts exist yet.

1. Copy `example.env` → `.env` (there is no `example.env` file yet; create it from `README.md` values: `PORT`, `NODE_ENV`, `MONGODB_URI`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`).
2. `server.ts` calls `connectDB()` then `app.listen(env.PORT)`. `env.ts` **throws** if `MONGODB_URI` is missing — MongoDB must be reachable before start.
3. Route wiring: `server.ts` → `src/app.ts` → `src/routes/index.ts` → feature routers under `src/modules/*`. Auth routes live at `src/modules/auth/auth.routes.ts` mounted under `/api/v1/auth`.
4. Imports use `.js` extensions even for `.ts` files (NodeNext ESM resolution), e.g. `import { router } from "@routes/index.js"`.
5. `dist/` is build output (gitignored) and committed artifacts exist from a previous build — ignore them.

### Frontend (`apps/frontend`)

Scripts: `dev` (`next dev`), `build` (`next build`), `start` (`next start`), `lint` (`eslint`).

- This is **Next.js 16** with breaking API changes vs older training data. Read `node_modules/next/dist/docs/` (resolved from `apps/frontend/`) before writing code; heed deprecation notices. `apps/frontend/AGENTS.md` is auto-regenerated by `next dev` — do not remove it from diffs; commit it with your work to keep the tree clean.
- Tailwind v4 via `@tailwindcss/postcss`; `globals.css` imports `tailwindcss` directly.
- App Router: `src/app/page.tsx` is `"use client"`; layout at `src/app/layout.tsx`.

### Shared (`packages/shared`)

Published as `@task-vault/shared` (`workspace:*`). Exports are file-mapped: `./constants` → `src/constants.ts`, `./validation` → `src/http/validation.ts`. Backend imports `@task-vault/shared/constants` and `@task-vault/shared/validation` directly from source (no build step needed for the backend to consume it).

## Gotchas

- `.env` and `.env.*` are gitignored (only `!.env.example` is allowed). No `.env.example` exists yet.
- Backend `tsconfig` uses `"module": "nodenext"` + `"verbatimModuleSyntax": true` — type-only imports must use `import type`.
- No test suite exists yet (roadmap lists Vitest/Supertest as planned). Do not invent test commands.
- `dist/` build output is gitignored but stale compiled files exist in `apps/backend/dist`; do not edit them.
- `apps/frontend/pnpm-workspace.yaml` exists at the app level but the real workspace root is the repo root `pnpm-workspace.yaml`.
